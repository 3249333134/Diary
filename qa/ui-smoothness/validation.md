# UI与操作流畅度优化验证

日期：2026-10-24。现有隔离演示：`http://127.0.0.1:4320/`。未重置真实日记，未发布线上。

## 问题与修复

实测主要瓶颈在折叠卡片：254条日程会同时创建所有隐藏详情、实体说明及两套选择控件。窗口约24,000节点、列表约22,500节点，产生0.8～0.95秒的主线程长任务。大量筛选还会重复创建日期格式器。接口在本地通常为个位至几十毫秒，没有把优化扩展成未经证实的后端改写。

- 折叠时仅创建摘要，展开后才创建详情和玻璃选择控件，收起清理浮层；保留卡片展开状态与原有数据。
- 复用日期格式器与当前分钟结果，跨分钟、跨日和时间倒退都重新计算；单元检查覆盖边界。
- 窗口、列表及四象限使用相同日期范围时不重复读取，修改、同步、日期范围及加载范围变化仍触发刷新。
- 桌面日程用上原右侧概览的空间，日记保留本周概览；窗口提供名称快速定位，私人／共享仍独立。
- 稳定的浅／深工作表面代替多层模糊叠加，保留紫色导航和玻璃弹窗；卡片标题、元信息、状态、表单及44px操作区域统一。手机输入16px；初始读取显示明确状态。

## 检查结果

- Web构建通过；保留既有主包体积提示。
- 34个测试文件、125项通过，新增日期时钟缓存边界检查。
- 三独立账号＋五宽度明暗主题：67组通过，见 `../social/functional/results.json`。
- 私人周／两周／月、多项改期与冲突恢复：本次375和1440浅色各13组通过。`../fortnight/results.json` 中其他宽度组合为历史记录，不冒充本次执行。
- 鼠标／触控平移、取消、滚轮、原生滚动、短视口和键盘：375和1440各7组通过，见 `pan-375.json`、`pan-1440.json`。
- 工作／个人生活／共享窗口及筛选恢复：三种宽度×明暗共6组通过，见 `../window-visibility/results.json`。
- 真实演示只读流程：375／768／1440×明暗6组通过，无页面错误、无日程写入请求。检查窗口快速定位、详情按需创建、编辑取消、日记与我的切换和无页面溢出。
- `git diff --check`通过，只有仓库既有换行提示。

宽屏增加可见面积后，部分测试已无需横向滚动，断言按实际溢出判断。快速导航后的滚动复位需要等浏览器两帧结束，短视口平移测试据此同步后验证；未为此修改实际平移逻辑。

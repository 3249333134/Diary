# 拖动、滑动与切换性能补充

日期：2026-10-24。交付位置：现有隔离演示 `http://127.0.0.1:4320/`。不重置日记、不发布线上。

## 定位与改动

用户优先反馈拖动、滑动及切换卡顿。继上一轮按需创建详情、复用读取范围之后，这次单独测量手势过程：四象限在每次指针移动时重新创建全部卡片，窗口每次修改left/top后立即读取布局，日历重复计算日期分组及密集卡片位置。

- 四象限和窗口的预览用transform跟随指针，每帧合并多次移动；只有目标象限／窗口改变时才更新对应状态。
- 日历复用日期、预览分组、小时轴及密集卡片位置。仍按15分钟吸附，但同一落点不反复更新整张日历；屏幕外任务统计不再随普通拖动反复拆装。
- 日历空白平移和卡片滑动每帧更新一次，松手先处理尚未绘制的最后位置。取消、切换及卸载清除排队工作，避免过期移动改变后续手势。
- 修复拖动中按Escape后松手误开编辑框；修复窗口长按激活前滑动取消时未恢复悬浮卡片及占位的问题。
- 保留多项改期的局部预览、确认才保存、独立期次、部分失败、冲突及写入成功后的刷新提示；没有后端或存储改动。

## 同条件前后测量

`scripts/qa-gesture-performance.mjs` 在现有演示数据上只读执行，375／1440宽度、Windows Edge、4倍CPU降速，每个视图在拖动激活后执行60次小范围指针移动，最后Escape取消。每次均验证没有写入请求。原始记录为 `baseline.json` 和 `after.json`。

| 测量 | 375优化前 → 后 | 1440优化前 → 后 |
| --- | --- | --- |
| 四象限脚本总耗时 | 3226ms → 430ms（减少87%） | 3280ms → 418ms（减少87%） |
| 四象限帧间隔P95 | 50.0ms → 16.8ms | 49.9ms → 16.7ms |
| 四象限超过25ms的帧 | 61 → 0 | 56 → 0 |
| 窗口布局计算次数 | 60 → 0 | 60 → 0 |
| 两周日历脚本总耗时 | 487ms → 158ms | 428ms → 148ms |
| Escape松手误开编辑框 | 是 → 否 | 是 → 否 |

这是本机单次、已加载数据的小范围拖动对比，不是所有手势或实际手机60fps保证。elapsed包含浏览器自动化往返，不作为操作响应时间。窗口手机脚本耗时没有下降（376ms → 384ms），改进来自布局次数和总主线程工作量下降。跨区域拖动另做功能验证。切换的节点数／长任务对比沿用 [上一轮记录](../ui-smoothness/validation.md)，不与本次手势时间混算。

## 验证结果

- Web构建通过，保留已有主包体积提示；35个测试文件、127项全部通过。
- 新增帧合并、最后位置同步处理及取消清理单元测试。
- `qa-gesture-regression.mjs`：375／1440共12组通过。覆盖同一浏览器任务内移动并松手、确认前零写入、Escape不误开编辑框、四象限归类、窗口任务归类、窗口排序及触屏长按取消，见 `regression.json`。
- `qa-calendar-pan.mjs`：375／1440各7组通过，覆盖鼠标／触屏横向、纵向及斜向平移、边界、取消、滚轮、固定表头、待确认预览、短视口及完成键盘操作。
- `qa-fortnight.mjs`：375／1440各13组通过，覆盖周／两周／月多项拖动、重复调整、确认、取消、部分冲突、刷新失败及远端修改。结果中的其他宽度为历史记录，不算本次执行。
- `qa-social.mjs`：三账号7组，以及375／624／768／1280／1440明暗主题60组通过；共享权限、多项改期、私人隔离、四类日记草稿、AI原文和全屏均保留。

一次手机回归与构建同时启动，前两项因资源切换超时，其余通过；构建结束后重新执行整组确认。此次没有更改CSS或追加外观截图，沿用上一轮已完成的批量视觉检查。

手机结果均为浏览器触控模拟；微信安卓实机、实际输入法与实际麦克风未验证。
